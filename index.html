Directiva Función Técnica Qué pasa si se elimina / cambia
FROM node:20-alpine Imagen base minimalista de Linux con Node.js v20. Falla el build. Sin alpine la imagen pesará 1GB en lugar de 180MB.
WORKDIR /app Directorio interno de ejecución. Los archivos se copian en la raíz (`/`) generando conflictos de sistema.
EXPOSE 8080 Documenta el puerto de escucha del contenedor. Si no coincide con `server.js`, la conexión será rechazada (`Connection refused`).
CMD ["node", "server.js"] Comando por defecto al iniciar el contenedor. El contenedor finaliza inmediatamente al no tener proceso principal activo.

Por defecto, los jobs corren en paralelo. Para bloquear el despliegue cuando una prueba falla, se requiere `needs`.

ci.yml 
name: ci-cd
on:
  push:
    branches: [main]

jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm test

  deploy:
    needs: build-test
    runs-on: ubuntu-latest
    steps:
      - run: docker build -t app:${{ github.sha }} .

Causa: Falta de `maxUnavailable: 0` en RollingUpdate o ausencia de `readinessProbe`.

Solución: Corregir el nombre y etiqueta de la imagen Docker en el manifiesto YAML.
Pod en CrashLoopBackOff
Causa: Falla en tiempo de ejecución al arrancar el contenedor o ruta/puerto de la probe erróneo.
Solución: Verificar logs con `kubectl logs ` y ajustar la ruta/puerto de readinessProbe.

Metodología de Diagnóstico Paso a Paso

Para resolver cualquier problema en evaluaciones o desarrollo, sigue esta metodología secuencial:

  1. Paso 1: Diagnóstico de Red en Contenedores: Verificar que `server.js` escuche en `0.0.0.0:8080` y que `Dockerfile` tenga `EXPOSE 8080`. Probando con `curl http://localhost:8080`.
  2. Paso 2: Diagnóstico de Endpoints en Kubernetes: Ejecutar `kubectl get endpoints web-service`. Si devuelve ``, ajustar la etiqueta en `template.metadata.labels` a `app: webapp`.
  3. Paso 3: Diagnóstico de CI/CD Pipeline: Verificar que el trabajo `deploy` tenga `needs: build-test`. Al salir `npm test` con error (`exit 1`), el despliegue se cancela.
  4. Paso 4: Diagnóstico de Alta Disponibilidad (El Giro): Verificar réplicas a 6, `maxUnavailable: 0` y sondas `readinessProbe` para garantizar cero caídas durante actualizaciones.
